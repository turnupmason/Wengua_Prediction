# 518400 条断词高速编辑：1080 原盘事实库 + 逐案证据 + 分组文学编辑

## 当前决定

不再在聊天窗口每次人工逐篇写 9–10 条。这种吞吐与 518,400 条不匹配；但也不能因为物理盘只有 1080 种，就把 1080 篇固定断词直接套到不同的月令、四柱、关系用神或冻结V8吉凶上。

**1080 是原盘物理布局数，不是最终可互换的断语数。** 对一名人物，518400/1080=480 只是平均，每个物理盘真实对应的有效案例数量须由输入数据决定。每条仍有独立案例、独立角色和原证据 SHA；意义相同的语句可自然相似，不为“独一无二”编事实。

## 已经实际可用的仓库能力

- 原始事实源：WenguaApp `scripts/wengua_bigfish_518400_offline_editorial_20261029.py`，按真实 BigFish 时家排盘缓存至 `physical_1080/`。每个抽象组合按冻结V8与实际月令/角色生成独立 `source_fact_lock`。输出按每 5000 行一组 JSONL / CSV / XLSX；一条 JSONL 含两个节气候选，本阶段只取 `branch=甲`。
- 新调度器：`tools/plan_1080_bulk_editorial.py`，纯 Python 标准库，无模型/API依赖。**本程序只是编辑任务分组，不生成任何文学稿，更不会重新评分。**
- 新验收：`tests/test_1080_bulk_editorial.py`，用合成数据验证同盘多案保留、来源失败隔离、两种盘分包、同输入可安全重跑、缺真实BigFish九宫时禁止进入下一步。
- 当前风格锚点：`case-000001-jieqi-a.v9.json`，第一屏约467字自然解释，第二屏十章有真实盘面专业证据；**两屏都禁止出现内部计分术语**。

## 在 Mac 上操作（直接复用现有 BigFish 计算结果）

把 WenguaApp 的原始 `*_待审事实包.jsonl` 文件所在目录、以及同一次生成的 `physical_1080` 目录，填入下面两个本地路径。运行时不会修改源目录。

```bash
cd /你本机的/Wengua_Prediction
python3 tools/plan_1080_bulk_editorial.py \
  --input "/现有批量结果/Excel_CSV_可直接打开" \
  --boards-root "/现有批量结果/physical_1080" \
  --out "./local/甲分支_518400_编辑分组_正式版" \
  --branch 甲 \
  --batch-size 200
```

小批试验用 `--max-new 20`，并**指定另一个新的 `--out` 目录**；正式全量版不要混用试验目录。针对 518,400 个真实合格的甲分支源记录，按每包最多200条，数量级是约2592个编辑包，按物理盘分开存放（实际因分组边界、失败与来源有效性可能更多）。不要理解为全部稿件已经写好。

产物在 **Mac 本地**，不是 GitHub 已有 518,400 份文学稿：

```text
local/甲分支_518400_编辑分组_正式版/
  editorial_queue.sqlite        # 每条独立事实、SHA、状态和坏源证据
  batch_manifest.json           # 各物理盘数量 / 类似事实签名 / 每包 SHA
  batches/
    yang-08-甲子/
      batch_0001.jsonl
      batch_0002.jsonl
    ...
  missing_original_boards.json  # 仅缺少原盘时生成，此时禁止继续
```

每条 JSONL 只含来源原始 `frozen_fact_lock`、`source_sections`、年/月/日/时、节气甲、原分级和原 SHA、真实物理盘路径和 SHA。**不复制此前已退稿的 v5/v7/v8 文学文字**。类似事实签名用于对照同类病势/医药关系、合理复用同一个判断思路，而不是把整篇文字直接复用于不同问测条件。

## 下一阶段：真正批量写作的正确架构

1. **1080个盘的专业共性事实档案**：每个真实物理盘只解读一次落宫、星门神、天地盘格、空墓刑迫等可共享事实。只缓存这些真事实，不缓存某一个父亲四柱的完整最终判断。
2. **逐条判断差量**：每条原始源事实锁中已经有角色主辅宫、五行、200格力量、源关系有效性、月令、应期和冻结总结果。这些必须以该条为准。将“共性盘事实＋本条差量”交给语言编辑模型，生成六角色第一屏和完整十章。
3. **分批语言模型写作**：批量任务并行、失败重试、按 SHA 续跑。每批内同盘而月令/角色/分级不同的条件都要独立输出；模型不能自行修改事实锁。使用 RTX4090 本地模型或受控API批量推理，需要单独建立实际推理后端并测10/100/1000条的真实吞吐，不能从规划成功推断文字生成已完成。
4. **多重审查**：源四柱与盘号SHA一一对应，原等级不变，按实际方向描述病宫与医生/药物/父亲关系；无依据不编疗效、病名、日期；检查中文标题、两屏术语、套话/反问、段落相似度。**相似事实不当错误**，区别仅在于是否错引不同条件。
5. **存储及正式发布**：源事实和新稿分开保留。几十万条不要在公开Git历史里逐个反复改写文件；用本地版本化 SQLite/JSONL 加GitHub汇总清单、审计SHA和问题清单。iOS离线资源只包含正式批准记录；模型自动草稿是`draft`，文学风格通过测试不等于用户批准发布。

## 不改变的底线

原 V8.0 冻结评分、200源强、81天地格、BigFish原盘、六甲用神绑定与Python/Swift一致性**一律不动**。当前没有真实出生年命就不补；父亲用问测年干，甲子年甲遁戊找宫、核甲自身力量，乾六只作男性长辈辅助。节气乙不编辑，也不能把节气乙误作时干。零分“微恙”与“不凶不吉”同义。

这份调度方案**不等于**1080个专家原盘档案、518400篇最终断词、批准SQLite已经完成。整个工程的速度取决于实际模型吞吐、审查失败率与证据差异数量，必须实际试跑后定量，不凭经验宣称几小时就能全部完成。
